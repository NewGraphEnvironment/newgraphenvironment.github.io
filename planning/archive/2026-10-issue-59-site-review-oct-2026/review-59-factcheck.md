## UAV detail to pull in

Facts about stac_uav_bc the site could add, each with its source (README fetched 2026-10-17; code read at `main`):

- Flight planning from the floodplain delineation: `scripts/flight_plan.py` (header, lines 1-7) reads the published stac-floodplains-bc floodplain over `/vsicurl/` with no download, selects a named reach (`--stream`), clips to a working radius of the launch point, splits it into blocks that each fit one battery, lays serpentine transects and writes one DJI WPML `.kmz` mission per block. It is idempotent (re-running overwrites the same block files). README lines 21-27 say the same. Verified in code; the asset path is hard-coded to the MORR `co_ff04` layer today.
- Three gated modules under it: `flight_coverage.py --selftest` (camera model against flown missions), `flight_budget.py --selftest` (endurance against seven flown missions), `flight_wpml.py --roundtrip` (writer against five Map Pilot exports). `flight_plan.py` header lines 9-13; all three files exist in `scripts/` (sizes 13,501 / 14,664 / 15,498 bytes).
- Stitching with OpenDroneMap: `scripts/odm_process.R` ("OpenDroneMap processing (orthomosaic, DSM, DTM generation)", README line 261), plus `odm_process-batch.sh` and `odm_qc.py` in `scripts/`; `cog_convert.R` converts the outputs to Cloud-Optimized GeoTIFFs (README line 260).
- Items carry flight capture datetimes and are queryable by location and time (README line 14-16). Live collection temporal extent: 2020-09-04T11:47:38Z to 2026-09-23T16:37:52Z (`images.a11s.one/collections`).
- Queryable via rstac, QGIS 3.42+ or any STAC client (README line 15-17); API endpoint `https://images.a11s.one`; single-COG viewer `https://viewer.a11s.one` (README line 17-19).
- Collection id `stac-imagery-uav-bc` (`imagery-uav-bc-prod` until v2.0.0; README line 47-48), live title "UAV Imagery from British Columbia - stac-imagery-uav-bc", licence CC-BY-4.0 (live collection JSON).
- Organised by region / watershed group / year, with regions skeena, fraser, mackenzie, kootenay (README line 117); COGs in the `imagery-uav-bc` S3 bucket (README line 77).
- Each item carries its site registry row: stream name(s), Freshwater Atlas watershed group code and name, the bcfishpass crossing id the flight covers, and an alias that separates repeat flights such as "moose pre-replacement" (README lines 115-124, `data/sites.csv`, 86 rows). Filterable with CQL2, e.g. every item in MORR (README lines 132-137).
- Elevation fit to provincial lidar: 46 datasets fitted to the LidarBC 1 m DEM; after the fit the ground misfits lidar by a median of 0.42 m (42 of 46 within 1 m); the fit is published on every item as `alignment:` fields, not yet applied to the rasters (`alignment:applied` false; README lines 141-199). This is the qualifier behind row 5 and also a feature worth stating.
- Use in the Neexdzii Kwah program: "UAV flights were conducted at the majority of sites to provide high-resolution baseline imagery for monitoring ... cataloged via stac_uav_bc" (restoration_wedzin_kwa_2024 §3.1, §4.1). The same report credits Matt Sakals (WLRS Provincial Drone Specialist) alongside NGE for some of that imagery (row 4).
